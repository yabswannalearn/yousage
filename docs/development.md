# Windows development setup

Install Git, Node.js 22.12 or newer, the Rust MSVC toolchain, Visual Studio Build Tools with Desktop development with C++, and the Windows SDK. YouSage uses the Microsoft Edge WebView2 Runtime. See the [Tauri Windows prerequisites](https://v2.tauri.app/start/prerequisites/#windows) for component selection. Run the commands below from the checkout in a fresh PowerShell session.

```powershell
npm ci
npm run tauri dev
```

Build the standalone executable with `npm run build:desktop` or include the NSIS installer with `npm run tauri build`. The Windows CI workflow runs the frontend build, TypeScript and Rust tests, and browser walkthroughs on pull requests.

The release workflow runs `tests/installer-smoke.ps1` on a clean Windows runner. It installs the published v0.1.0 package, launches it, upgrades to the candidate package, checks that local data survived, and uninstalls it. The workflow accepts a manual dispatch for an installer check before tagging.

Keep the standalone executable and installer signed with the same trusted publisher identity once a signing identity is available. Configure [Tauri Windows signing](https://v2.tauri.app/distribute/sign/windows/) in the release workflow, then verify both final artifacts with `Get-AuthenticodeSignature` before upload. Review the [SmartScreen reputation guidance](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation) when rolling out signed builds.

## Integration

YouSage uses the documented Codex app-server account API over local standard input/output, the Google Antigravity CLI (`agy -p "/usage" --output-format json`) for Antigravity model quota groups, and Claude's account metadata endpoint for subscription usage. Usage checks do not start model turns or consume model tokens.

The Codex desktop connection follows `CODEX_HOME` (default `%USERPROFILE%\.codex`); during integration probing, its account usage matched the desktop app's reported usage. Additional Codex sign-ins use app-local account homes with Codex's OS credential-store mode.

Antigravity usage follows the active local sign-in in `%USERPROFILE%\.gemini` (reading only the non-secret active email from `google_accounts.json` and quota buckets from `agy`). YouSage never sends tokens to the interface or saves them in its settings/cache files.

Each Antigravity quota check runs in a temporary auth-only home and working directory. User and project MCP settings, plugins, and hooks are not copied, so `/usage` cannot start configured MCP command windows. Temporary sign-in files are kept under the user's local app data rather than a potentially shared Windows `TEMP`, and removed when the process finishes or times out. Switch staging/backups use the same location. Refreshed credentials are saved back only if the source sign-in has not changed during the check; normal CLI configuration is never modified.

`YOUSAGE_CODEX_BIN` and `YOUSAGE_ANTIGRAVITY_BIN` can select specific Codex or Antigravity (`agy`) executables if installed outside their usual locations.

Startup registration is applied in release builds. Development builds do not register themselves to run at Windows sign-in.

The browser-only `?preview=1` route in development shows explicitly labeled demonstration data for Codex, Antigravity, and Claude; real account access requires the Windows app.

Claude reads the existing subscription OAuth credential from `%USERPROFILE%\.claude\.credentials.json`, honoring `CLAUDE_CONFIG_DIR`, and queries `https://api.anthropic.com/api/oauth/usage`. It uses the system `curl` already used by the update checker, passes its authorization header through stdin, and never passes tokens in process arguments. The endpoint is internal and is not a supported public API. Checks have a five-minute minimum interval, with a fifteen-minute minimum backoff on HTTP 429; a longer numeric `Retry-After` is honored. Claude Code owns login and token refresh. The preview route also includes Claude demonstration data.

Provider accents and visibility are saved in `settings.json` as `providerColors` and `hiddenProviders`. Existing settings gain defaults without losing connected accounts. Hiding preserves credentials, colors, and the preferred notch source; background polling continues while readings and alerts are omitted. The frontend temporarily selects a visible source and restores the preference when it becomes visible again.

Usage alerts use Windows WinRT directly through src-tauri/src/notifications.rs. Portable builds register a per-user Start Menu shortcut with the app user model ID; development uses a separate identity. Native Show errors and asynchronous Failed callbacks are retained in diagnostics. Windows settings determine delivery availability and banner suppression. API acceptance and Notification Center history do not prove that a banner was visible. Privacy-aware alert delivery and clearing old notifications share a gate to prevent an in-flight refresh submitting an old account name after privacy is enabled.

The independent `appTheme` setting stores six-digit hex `background` and `accent` colors, with defaults for older settings files. `src/theme.ts` derives shared surface and text tokens and adjusts accent text for contrast; subscription colors remain unchanged. Color picker input previews without replacing the DOM, and committed changes persist through the existing settings command. Reset affects only the app theme. Theme tests cover light, dark, saturated, invalid, and reset values.

The native drag command marks the gesture as active until the mouse is released. Outside-click collapse and frontend rendering are deferred during the gesture, and the release click stays suppressed until the next intentional pointer press. This prevents a long drag from outlasting a fixed click-suppression timeout and hiding the expanded contents. The native color picker also suspends automatic collapse while open.

Docking is stored as `dockEdge` alongside the existing `anchor`; older settings default to floating. Native drag completion snaps to the nearest work-area edge within 28 logical pixels. Left/right compact windows are 58 × 184 logical pixels; top/bottom are 480 × 40; floating is 440 × 80. Top/bottom detail panels retain their 480-pixel width; side detail panels expand to 440 pixels. The existing window expands inward and publishes `notch-layout` so the frontend matches its native bounds. Monitor fallback and DPI conversion remain in the native placement path. `node tests/docking-ui.mjs` checks all docking layouts against preview data with Vite running, writes screenshots under `artifacts/docking/`, and verifies fit, expansion and Escape. Preview URLs accept `?preview=1&edge=left` (or right/top/bottom).

`npm run test:ui` exercises the real frontend against a mocked Tauri bridge while the Vite server is running; it requires Playwright Chromium (`npx playwright install chromium`). It covers long drags, focus changes, release clicks, color-picker focus, separate accents, preview selection, and hiding/restoring every subscription. These checks do not verify an actual Windows drag gesture or a live Claude account. Run the built Windows app for those checks; live Claude data requires a valid subscription sign-in.

## Account switching

Switches preserve the existing Codex home and change only its Codex auth credential. Connected accounts use Codex 0.160's `secrets/codex_auth.age` file and the corresponding master password in Windows Credential Manager. The canonical home path determines the credential-store entry; other Codex secrets are left intact. The destination respects the effective `cli_auth_credentials_store` value read from Codex. Crypto runs on blocking workers rather than the interface thread.

Before either provider's switch, YouSage validates the chosen sign-in and shows a confirmation naming the apps and terminal shells that will be force-closed. Codex checks ChatGPT/Codex desktop apps, standalone Codex CLI sessions, and their related terminal shell trees (including the npm Codex shim). Antigravity checks its desktop app and `agy` sessions. Other terminal tabs and unrelated applications are not selected. YouSage's own usage helpers are excluded, and switches refuse to close an ancestor of YouSage itself. This classification uses a full Windows process snapshot so terminal ancestry is available; command lines remain backend-only.

After confirmation, process identity (PID, start time, executable, and name) is rechecked before each targeted `taskkill /T /F`. The switch waits until the provider's sessions have stopped; if a process survives or respawns, no active credentials are replaced. If sessions appear after a confirmation that listed no running processes, the switch asks for confirmation again. Desktop apps are reopened after the transaction; CLI sessions must be started again by the user. Force-closing interrupts tasks and can lose unsaved work, which the confirmation explains.

After shutdown, Codex saves the latest outgoing credentials to a connected account, replaces the active credential, and verifies the account through a new app-server process. A verification failure restores the old credential. Only the active connection refreshes an active account, avoiding competing refresh-token rotation from its saved connection. Antigravity stages its validated target, backs up the outgoing sign-in, synchronizes the complete credential file set (removing stale files absent from the target), and checks usage before reopening the desktop app. A replacement or usage-check failure restores the previous sign-in. Antigravity switching honors `GEMINI_CLI_HOME` for the active destination.

To test encrypted-store interoperability without using a real account:

```powershell
. ./scripts/tools.ps1
cargo test --manifest-path src-tauri/Cargo.toml isolated_codex_keyring_compatibility -- --ignored
```

This opt-in Windows test creates a disposable Codex home and a dummy API credential, verifies Codex/YouSage compatibility, then removes the test credential and directory. It does not switch the user's Codex account.

Antigravity's background updater launches `agy --version` in a new console during quota checks. On systems using Windows Terminal as the default terminal, a separate brokered terminal window can appear even when the CLI's own console is hidden. Usage checks set the process-local environment variable `AGY_CLI_DISABLE_AUTO_UPDATE=true` (the literal `true` is required; `1` does not work). Normal interactive CLI sessions and their updates are unchanged. Usage polling launches agy directly with `CREATE_NO_WINDOW`; the previous PowerShell/cmd wrapper and its Job Object were removed. Authentication isolation and refresh behavior are unchanged.

For a Windows integration regression, run `./tests/console-windows.ps1 -AppPath ./src-tauri/target/release/yousage.exe -RestartApp`. This restarts only the named executable, observes its process tree and actual console/Windows Terminal show events for 80 seconds, and fails on internal agy updater children or visible console events correlated with background CLI launches. Keep the desktop otherwise idle so unrelated terminal launches are not mistaken for the app's. The test uses existing sign-ins for normal quota checks; it does not switch accounts. The older synthetic hidden-console inheritance test did not cover Windows Terminal delegation and has been removed.

Circular meters replace compact and detail allowance tracks. Compact readings include reset countdowns, updated in place every 30 seconds without replacing controls; tooltips and detail cards show full reset times. Unknown usage stays a dash with an empty ring.

Usage preferences are stored under `usagePreferences` in settings and exposed through the snapshot. Older settings gain defaults. `update_usage_preferences` validates and saves custom notch providers/window selection, provider alert rules, quiet hours/snooze, and recommendation preferences. Account preference keys include the provider (`codex:<id>` or `antigravity:<id>`) to keep the two account lists independent. Timestamps use Unix seconds; frontend comparison helpers accept the JavaScript clock in milliseconds.

`src-tauri/src/usage.rs` contains preference validation, alert observations, and connection-health types. Quiet hours use Windows local time. Alert observations and provider health are persisted locally; suppression still advances notification observations to avoid a backlog. History and pacing live in src-tauri/src/history.rs. Local bounded JSON stores successful samples using hashed identities and generic aliases, with five-minute sampling and hourly compaction after seven days. Unchanged history is not rewritten. Forecasts require recent monotonic samples in the same reset window; failed, stale, sparse, or discontinuous observations suppress estimates. Retention supports 7/30/90 days. CSV export honors privacy mode and escapes formula-leading labels.

## Background resource use

Scheduled checks skip paused providers. Manual refresh and account-management actions can still check them on demand. The first check after launch includes saved accounts. Later scheduled Codex and Antigravity checks run for active accounts every refresh interval and for inactive saved accounts at most once every five minutes. Claude keeps its own retry and rate-limit policy.

Provider usage checks publish a start and completion snapshot. The collapsed notch keeps its existing controls and updates changed readings or session text. Tray updates compare the tooltip and attention state before setting them. Persistence skips identical settings, usage caches, and alert data. The Windows pointer watcher waits 500 ms while hidden and checks visible pointer movement every 40 ms to keep the dwell responsive.

To measure a Windows release build on modest hardware, use a clean Windows user on a 4 GB PC or VM. Record the time from launch to usable dashboard, the time from hover to expanded panel, and the process-tree private memory after one minute. Then hide the notch to the tray and sample CPU time, private memory, and child process starts over at least ten minutes. Repeat with one signed-in provider and several saved accounts, then pause that provider and repeat. Include WebView2 descendants and label the Windows and WebView2 versions. Compare to the same workload on the previous build before deciding whether to suspend the hidden WebView.

## Hover, session status, and Claude switching

The compact header expands after a 200 ms rest on the visible bar's top 3 pixels. Its collapsed surface passes clicks to the window underneath. Clicking anywhere inside the detail panel pins it; pointer departure minimizes only an unpinned panel. Native polling observes real screen-coordinate movement and outside mouse presses, including when the hover preview never had focus. Focus loss alone no longer collapses. Timed native resize/pointerleave events do not close a stationary preview, and drag/color-picker guards remain in effect.

`src-tauri/src/sessions.rs` handles a windowless executable mode (`--yousage-session-event`) before Tauri initializes. Codex and Claude Code hooks feed only normalized metadata into app-local session files. Session IDs are SHA-256 hashed; prompts, arguments, full workspace paths, and tokens are never saved. Process IDs plus creation times remove ended/crashed processes without confusing recycled PIDs. Session files expire after 24 hours. The watcher emits visible changes without rerendering for timestamp-only updates. Status tracking is opt-in through Settings, merges existing hook handlers, and removes only YouSage's entries on disable. Codex hook trust remains user-managed.

Antigravity uses its named `~/.gemini/config/hooks.json` schema with an explicit event argument and camelCase inputs. CLI status-line state supplies `tool_confirmation_pending`, `agent_state`, and idle transitions. The observer stacks silently with the default status line, or forwards the original custom command from a local backup. Disabling restores the original `statusLine` object. App/IDE hooks include `ask_permission`, `ask_question`, blocking `notify_user`, and `Stop.fullyIdle`; they do not expose all automatic permission dialogs. These integrations follow the provider documentation linked in README.

Claude's `seven_day_*` model counters are independent weekly windows. `seven_day_overage_included` (the legacy bucket labeled Fable by the installed Claude Code client) and `seven_day_fable` expose Fable and its own reset; an explicit Fable bucket takes precedence if both are present; missing or null model buckets do not create fake counters. `claude:<model>` is a saved notch source. Existing Claude caches and settings migrate with empty model/account lists.

`claude_accounts.rs` saves each Claude Code credential payload using Windows user-bound DPAPI in app-local `claude-accounts/*.bin`. Only labels/IDs enter settings; only account metadata enters snapshots. Switching validates the target before closing processes, uses the existing explicit process review, saves the outgoing sign-in after shutdown, and replaces only credentials and the `oauthAccount` field. Failed replacement restores previous bytes. Unrelated Claude settings/projects are preserved. Desktop Claude has independent authentication and is excluded. Native/API integration with real sign-ins is intentionally excluded from automated tests.

Verify with `npm test`, `npm run build`, `cargo test --manifest-path src-tauri/Cargo.toml -j 1`, and, with Vite running, `node tests/notch-sessions-ui.mjs`, `node tests/desktop-ui.mjs`, `node tests/docking-ui.mjs`, and `node tests/history-privacy-ui.mjs`. The new UI test saves demonstration screenshots under `artifacts/notch/`.

`src-tauri/src/auto_switch.rs` implements opt-in exhaustion switching after scheduled or manual usage refreshes. `usagePreferences.autoSwitch` holds provider booleans and `sessions` (`wait` by default). The `close` policy also requires `forceCloseConfirmed`, which is set by choosing the force-close option. Targets respect purpose and suggestion exclusions. It requires exact 0%, successful recent readings, not-yet-due reset windows, and positive comparable target windows. Antigravity compares the selected group, and a selected Claude model adds its own weekly constraint. Claude target usage is validated on demand; other providers rank already fresh saved readings. Revalidation runs within each switch I/O transaction before closing sessions and before replacing credentials, so changed settings/accounts cancel pending switches. Manual switching retains its explicit review. Generic status and a five-minute retry timestamp persist in `auto-switch-state.json`; provider cooldowns remain authoritative. No automated test switches real credentials or closes user sessions.

Collapsed surfaces are visually limited to 320 × 26 at horizontal edges (44 pixels tall when floating), within the existing transparent placement window so centering and expansion anchors stay stable. `set_expanded` toggles native cursor-event ignoring: collapsed clicks go to underlying apps; expanded controls are interactive. Native cursor polling observes the visible bar's top 3 logical pixels even while Windows routes mouse input through the window. A 200 ms dwell opens it once per entry; leaving the strip rearms it. The browser preview mirrors this geometry with pointer events disabled on the compact surface. Keyboard/tray opening remains available. `desktop::reveal_tests` covers the visible strip on every edge, while the UI checks verify body crossings and quick top-edge crossings stay closed.

Provider logos live in `src/assets/`; compact rings center the mark independently of the ring percentage. Empty headers omit the old provider summary and rest dot. Session titles are optional metadata; the header prefers a working session, then a permission request, then the first remaining session. Antigravity passes its conversation title through the live status-line feed; Codex can read a stored `thread.name` through a one-second, metadata-only local app-server request on lifecycle events when a supplied title is missing. It does not subscribe, resume, read turns, or start model requests. Privacy clears the render copy's title and uses session aliases. Existing session files migrate with a missing title.
